# 服务商预设（Provider Presets）实现方案

> 状态：**只留方案，等你确认后再动手**。对应需求：「把主流的国内和国际中转站以及大部分官方 API 留成可选项，
> 不需要让用户填地址，选了服务商填 Key 就行」。
> 一句话：把现在这一行「接口地址」升级成**服务商列表**——选一家、填一把 Key、选一个模型，其余全部预设。

---

## 1. 用户能感知的变化 / 开关 / 默认值（三件套）

| 项 | 内容 |
|---|---|
| 一句话变化 | 设置→接入里不再要求手打地址：点「服务商」，从列表里选一家（DeepSeek / Kimi / GLM / 通义 / 豆包 / 硅基流动 / OpenAI / Anthropic / Gemini / OpenRouter / Groq …），只需填 Key，再选模型就能用 |
| 开关 | 「服务商」选择器本身就是开关：选回 **DeepSeek 官方** 即完全恢复当前行为（地址、模型、余额、语音全部照旧） |
| 默认值 | 默认服务商 = **DeepSeek 官方**；默认模型 = `deepseek-flash`；默认协议 = 该服务商注册表里写死的协议（用户看不到协议，也不需要懂） |

---

## 2. 它解决什么问题（现状三条硬约束）

1. **协议只有一种**：`services/api/client.ts:21` 把聊天固定拼成 `${base}/anthropic/v1/messages`（Anthropic Messages 格式，`x-api-key`，SSE）。
   绝大多数国内外服务商只提供 **OpenAI Chat Completions**（`/v1/chat/completions`，`Authorization: Bearer`），路径与鉴权都对不上。
2. **模型名写死**：`services/api/models.ts` 只有 `deepseek-flash` / `deepseek-v4-pro` 两项，界面没有自定义模型输入。
3. **只有地址可换**：`features/settings/SettingsPage.tsx:91` 的「接口地址」只能改前缀，用户仍然要自己知道
   `https://xxx/anthropic/v1` 这种拼接规则——这正是"必须让用户填地址"的根源。

结论：**只做"预设地址表"不够，必须同时做协议适配层。** 这是本方案的主工作量。

## 3. 数据与接口变更

### 3.1 服务商注册表（新积木 `features/providers`）

```ts
type Protocol = 'anthropic' | 'openai'

type Provider = {
  id: string              // 'deepseek' | 'openai' | 'openrouter' …
  name: string            // 界面显示名
  group: 'official-cn' | 'official-intl' | 'aggregator' | 'custom'
  protocol: Protocol      // 决定走哪条客户端
  baseUrl: string         // 只写核实过的地址
  chatPath: string        // 关键：不再硬编码 /anthropic/v1/messages
                          //   DeepSeek: '/anthropic/v1/messages'
                          //   Anthropic 官方: '/v1/messages'
                          //   OpenAI 兼容: '/v1/chat/completions'
  modelsPath?: string     // 默认 '/v1/models' 或 '/models'，用于拉模型列表
  auth: 'x-api-key' | 'bearer'
  filePath?: string       // 附件：DeepSeek '/anthropic/v1/files'；OpenAI 兼容走 image_url，不填
  voice?: { asr: string; tts: string }   // 仅 DeepSeek 有
  balancePath?: string    // 仅 DeepSeek '/user/balance'
  contextLimit: number    // 1M / 128k / 200k…，供状态栏与压缩阈值用
  modelMode: 'fixed' | 'remote' | 'manual'   // 固定两项 / 拉列表 / 手填
  fixedModels?: string[]  // DeepSeek 用
  note?: string           // 界面一行说明（例如"仅支持图片，不支持文档"）
}
```

**首批候选清单**（按用户要求覆盖国内 + 国际 + 聚合；地址与模型名**必须在实现时逐家核对官方文档**，
核对结果回写本文件附录，未核实的一律不进代码）：

| 组 | 候选 |
|---|---|
| 国内官方 | DeepSeek、月之暗面 Kimi、智谱 GLM、阿里通义千问、火山方舟（豆包）、腾讯混元、MiniMax、阶跃星辰、百度千帆 |
| 国内聚合 | 硅基流动 SiliconFlow、302.AI、AIHubMix、DMXAPI |
| 国际官方 | OpenAI、Anthropic、Google Gemini、xAI Grok、Mistral、Groq、Together、Fireworks、DeepInfra、Cerebras |
| 国际聚合 | OpenRouter |
| 自定义 | 最后一项「自定义网关」（自填地址 + 协议），**保留**——个人中转站域名各不相同，枚举不完 |

### 3.2 协议适配层（`services/api/` 内最小改动）

- 抽象成 `ChatProtocol` 接口：`buildRequest(target, body) → {url, init}` 与
  `parseStream(response) → AsyncGenerator<MessageStreamEvent>` 两个方向。
- `anthropic` 实现 = 现有逻辑原样搬迁（`client.ts` 的 `streamMessage` + `parseEvent.ts`），行为不许变。
- `openai` 实现（新增）：
  - 请求：`messages[]`（system 单独一条）、`temperature`、`stream: true`、`max_tokens`；
    历史里的 `thinking` 块**降级为纯文本丢弃**（OpenAI 无 signature，保留会 400）。
  - 响应：`choices[0].delta.content` → 文本块增量；`finish_reason` → `message_stop`；
    `data: [DONE]` 作结束标记。
  - **usage 归一**（这是必须做的一格，否则状态栏与诊断日志全空）：
    `prompt_tokens → input_tokens`、`completion_tokens → output_tokens`、
    `prompt_tokens_details.cached_tokens → cache_read_input_tokens`、`cache_creation_input_tokens = 0`。
  - 错误码归一：401/402/429/400/413 映射到现有 `errors.ts` 的 `ApiErrorKind`，文案沿用中文。
- **平台层只读桥**：`platform/runtime.ts` 已有 `setApiOrigin/apiOrigin`；改为
  `setApiTarget({protocol, baseUrl, chatPath, auth, …})`，`services/api` 只读，不认识"服务商"概念
  （与现有 `safetyCheck` / `numberOption` 同一模式，`check-deps.mjs` 不受影响）。
- `services/chat/store.ts` 里 `tools: [deepseek_read_url]`（`:1130`）在 `openai` 协议下**不发**；
  「智能搜索 / 深度思考」两个胶囊在 openai 协议下置灰并给一行说明（该服务商不支持）。

### 3.3 设置存储

| 键 | 内容 |
|---|---|
| `gaia:provider` | 当前服务商 id（默认 `deepseek`） |
| `gaia:providers` | `{ [providerId]: { model, key? } }` —— **每个服务商各存一把 Key 和自己的模型**，切换不用重填 |
| `gaia:api-base` | 仅 `custom` 服务商使用（保留旧键，避免老用户升级丢配置） |

> 现有 `chat-demo:api-key` 作为 `deepseek` 那一格迁移过来；迁移只读一次，迁移后不再写旧键。

### 3.4 连带受影响的三处（都要处理，否则会出"看起来坏了"）

| 位置 | 现状 | 非 DeepSeek 时的处理 |
|---|---|---|
| 余额页 `features/account/api.ts:40` | `GET {base}/user/balance`（DeepSeek 私有） | 显示「该服务商不提供余额查询」，不发请求 |
| 语音 `services/api/speech.ts:9` | `{base}/v1/tools/{asr,tts}`（DeepSeek 私有） | 朗读/按住说话按钮隐藏（不是报错） |
| 上下文上限 | `CONTEXT_LIMIT = 1048576` 写死 | 取服务商注册表的 `contextLimit`，状态栏百分比与压缩阈值跟着变 |

## 4. UI 入口

设置 → 接入（现有两个二级页的父页改造）：

```
接入
 ├─ 服务商        →  列表页：分组（国内官方 / 国内聚合 / 国际 / 自定义），当前项打勾
 ├─ API Key      →  为"当前服务商"填 Key；标题带服务商名，避免填错
 ├─ 模型         →  remote：拉 /v1/models 下拉；fixed：两项；manual：文本框
 └─ 自定义网关   →  仅当服务商=自定义时出现：地址 + 协议（OpenAI 兼容 / Anthropic 兼容）
```

样式沿用现有 `SettingsPage.tsx` 的整屏竖排 + `rows.tsx` 行样式，不新造组件体系。

## 5. 成本影响

- **提示词装配完全不动**：`system` 里仍然只有人设/技能/摘要/长期记忆，时间与召回仍在尾注（§3.1 铁律 1）。
  换服务商不会改变我们发出去的内容形状，只是接收方变了。
- **但缓存经济性会变**：§5 实测的 73~85% 命中是 **DeepSeek 前缀缓存**的口径；
  OpenAI 的自动缓存按 1024 token 前缀段、Anthropic 是显式 `cache_control`（我们不发），
  Gemini/OpenRouter 又各不相同。**换服务商后状态栏的"缓存命中 %"只能用各家 usage 字段如实显示，
  不做推算，也不承诺命中率**。
- 因此：本功能不增加任何"每轮请求变长"的内容，成本风险仅为"用户以为换了家还能命中 85%"。
  处理方式 = 模型页下方一行说明 + 状态栏照实显示。

## 6. 风险与回滚

| 风险 | 说明 | 兜底 |
|---|---|---|
| 预设地址/模型过期 | 服务商改名、模型下架是常态 | 地址与模型走注册表单一文件；`remote` 模型列表运行时拉取；设置页保留「自定义网关」出口 |
| 协议差异导致的隐性错误 | 第三方对 `max_tokens`、`system` 位置、`stream_options` 宽容度不同 | 每家注册表加 `compat` 位（如 `omitStreamOptions`），不做"自动嗅探" |
| 跨协议续聊 | 从 DeepSeek 切到 OpenAI 模型，历史里的 `thinking` 块无 signature | 降级为纯文本；不删本地数据，切回 DeepSeek 仍按原样发送 |
| 一块崩 | 新积木 `providers` 若抛错 | `defineBlock` + `flags.providers`，崩了只这一块空白（默认 true） |
| Key 越权外泄 | 每服务商一把 Key，切换时发错家 = 把 A 的 Key 发给 B | 请求前断言 `provider.key === target.key`，不一致直接拒发并提示（比加密更关键） |

**回滚**：`flags.providers=false` 或把 `gaia:provider` 设回 `deepseek` → 行为等同 1.8.13；
代码层不删旧路径（`anthropic` 客户端即现有实现），因此回滚不涉及数据迁移。

| 批 | 内容 |

| P1 | 注册表骨架 + 协议抽象 + openai 客户端 + usage 归一 + 设置页改为「服务商 / Key / 模型」+ 余额与语音的降级 + DeepSeek 官方与 2~3 家已核实服务商 |

**验收口径**（做的时候照这个验）：

1. 不选服务商、不填地址，默认状态与原版逐字节一致（抓包对比 `/anthropic/v1/messages` 请求体）。
2. 选一家 OpenAI 兼容服务商 + 填 Key：能流出文字、状态栏有 token、`thinking` 块不出现在请求里。
3. 切服务商：Key 不串门（用错误 Key 验证拒绝路径）。
4. 余额页/语音在非 DeepSeek 服务商下按 §3.4 降级，不报错。
5. 压缩、档案卡、记忆召回在 openai 协议下照常工作（回归 §3.1 装配顺序）。
6. `build-all.ps1` 通过（tsc 零错误 + `check-deps.mjs` 不拦），真机走通。

> 验收需要你提供**至少一把第三方 Key**（哪家都行）；没有真 Key 只能验到 mock，不算通过。

## 8. 待你确认的决策点

1. **「主流中转站」怎么覆盖**：预设固定域名的大平台 + 保留一个「自定义网关」出口？（个人中转站域名各不相同，枚举不完）

5. **要不要顺手把 Key 加密**（原生 AndroidKeyStore）：这属于动原生层，不在本功能范围内，需你单独点头；不做的话 Key 仍明文在 localStorage。

## 9. 实施记录（1.8.13-beta.2，2026-11-20 22:48）

决策点按推荐项全部确认：固定域名预设 + 保留自定义网关；运行时拉模型 + 手填兜底；思考块降级为纯文本；每服务商各存一把 Key；**Key 仍明文存 localStorage（未加密，等单独点头）**。

**已落地**

| 层 | 改动 |
|---|---|
| 平台 | `platform/runtime.ts` 新增 `ApiTarget`（协议/地址/路径/鉴权/能力位）+ `setApiTarget`/`currentApiTarget`；新增 `setTextOption`/`textOption`（设置页显示当前服务商名） |
| 协议 | 新增 `services/api/openai.ts`（请求翻译 + SSE 解析 + usage 归一）；`client.ts` 按目标分派：DeepSeek 原路径逐字节不变，第三方 Anthropic 原生走纯文本 + `max_tokens 8192`，OpenAI 兼容走转换层（400 时去掉 `stream_options` 重试一次） |
| 积木 | 新增 `features/providers`（注册表 / store / 整屏页），`defineBlock` + `flags.providers`；设置页「接口地址」换成「服务商」，返回键优先级 75，overlay z-index 70 |
| 降级 | 余额页按 `balancePath` 判断、语音按 `voiceBase` 判断（缺了给可读提示，不静默）；上下文上限按注册表走（压缩阈值、状态栏百分比跟着变） |

**与方案的差异（要知道）**

1. **附件 P1 不发**：图片/文档降级为 `[图片]`「[文件]` 文字占位，没有做 `image_url` Base64 —— 需要读本地 blob，留到 P2。
2. **语​音按钮不隐藏**：点了给「当前服务商不支持语音，请切回 DeepSeek 官方」，改上游输入区 UI 的风险留到下一轮。
3. **Anthropic 原生**输出上限固定 8192（第三方必填 `max_tokens`，我们拿不到各家上限）。
4. 首批只收**核对过地址**的 12 家 + 自定义；名单里没写的（MiniMax / 阶跃 / 302.AI / AIHubMix / DMXAPI 等）等核实后进 P2。
